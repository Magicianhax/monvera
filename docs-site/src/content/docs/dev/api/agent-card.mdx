`GET /.well-known/agent-card.json` returns Vera's ERC-8004 discovery document: her name, skills, registrations, and the on-chain values an agent or crawler needs to check her, including her live agent signer.

- **Method and path**: `GET https://monvera.best/.well-known/agent-card.json`
- **Auth**: none (public)
- **Rate limit**: none; cached at the edge with `Cache-Control: public, s-maxage=3600, stale-while-revalidate=21600`

The card is served dynamically, not from a static file. Two fields are read live from chain 4663 on every request: `metadata.agentSigner` from the VeraRecord contract's `agentSigner()`, and `metadata.identityRegistry` from chain config. Read the card to learn the current signer instead of hardcoding it, because the signer can rotate.

## Parameters

This route takes no parameters.

## Returns

A JSON object with these top-level fields, in order:

| Field | Type | Description |
| --- | --- | --- |
| `name` | string | Vera. |
| `description` | string | What Vera does, in one paragraph. |
| `image` | string | `https://monvera.best/icon-512.png`. |
| `active` | boolean | `true`. |
| `persona` | object | `{ role, blurb }`. |
| `services` | object | `{ web: { url } }`. |
| `endpoints` | object | `{ app, agent, strategies }`, all on `monvera.best`. |
| `supportedTrust` | string[] | `["reputation"]`. |
| `skills` | string[] | Five skill ids (portfolio-allocation, plain-language-allocation, dca-autopilot, trading-strategy, risk-management). |
| `domains` | string[] | `["finance", "investing", "real-world-assets"]`. |
| `x402` | boolean | `false`. Vera does not gate this identity behind an x402 payment. |
| `registrations` | object[] | One entry: Vera's canonical ERC-8004 identity on Base. |
| `metadata` | object | Chain, registry, and live signer values (below). |

`registrations[0]` records the canonical identity: `agentId` 58228 in registry `eip155:8453:0x8004a169fb4a3325136eb29fa0ceb6d2e539a432` on Base, registered via Virtuals ACP. `metadata` carries `version`, `chain`, `chainId` (4663), `app`, `demo`, `agentPage`, `explorer`, `identityRegistry` (Monvera's own IdentityRegistry on 4663), `agentId` (defaults to 1), `agentSigner` (read live), and a `note`.

<Aside type="note" title="Two identities, documented honestly">
The card labels Vera's Base identity (`8453:58228`) as canonical, and also lists her as agent #1 in Monvera's IdentityRegistry `0x751ae640cfa816404b017fbb8234dd21abafbbdc` on chain 4663. Both are real. See [Verify Vera](/dev/verify-vera/) for the runnable chain from this card to a recovered signer.
</Aside>
