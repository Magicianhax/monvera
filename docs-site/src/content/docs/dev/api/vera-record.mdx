<Badge text="GET" variant="tip" /> <Badge text="Public" variant="note" /> `https://monvera.best/api/vera-record`

GET Vera's verifiable track record straight from the on-chain event log: how many recommendations she has committed, how much USDG has settled against them, her most recent plans, and her IdentityRegistry reputation score. Pass `?user=0x...` to scope the record to one account, or omit it for Vera's global record. Public chain data, no token. Rate limited to 30 requests per 60 seconds per IP.

Each recorded recommendation is the risk assessment Vera signed with her `agentSigner` key. The user separately signed the spend. This route reports what was recorded on-chain. To recover the signer of a `RiskInference` payload and confirm it equals `agentSigner()`, follow [Verify Vera yourself](/dev/verify-vera/).

## What it returns

A `record` object aggregated from Vera's `RecommendationCommitted` and `AllocationExecuted` logs on chain 4663, plus a `reputation` field read live from the IdentityRegistry. Empty history returns a clean zero-state, not an error.

## Parameters

| Name | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `user` | address | no | global | Restrict the record to one account. An invalid address returns 400. |

## Returns

| Field | Type | Description |
| --- | --- | --- |
| `record.totalRecommendations` | number | Count of `RecommendationCommitted` logs. |
| `record.totalExecutedUsd` | number | Sum of USDG settled across executed plans (6-decimal amounts as a number). |
| `record.executedCount` | number | Count of `AllocationExecuted` logs. |
| `record.recentRecommendations` | array | Up to 8 plans, newest first. |
| `record.recentRecommendations[].planId` | bytes32 | The single-use plan id. |
| `record.recentRecommendations[].riskScore` | number | Assessed risk in basis points. |
| `record.recentRecommendations[].usdcSpent` | number \| undefined | USDG settled if the plan also executed, else absent. |
| `record.recentRecommendations[].txHash` | bytes32 | The transaction that recorded the plan. Open it on Blockscout. |
| `record.recentRecommendations[].blockNumber` | number | Block the record landed in. |
| `reputation` | string \| null | Vera's `reputationScore(agentId)` as a decimal string, or null if the registry read is unavailable. |

<Aside type="note" title="Reputation reads zero until feedback is written">
`reputationScore` is owner-updated through feedback only, so it reads `"0"` until feedback exists. A `"0"` or `null` reputation is honest, not an error. Do not read it as a live performance score.
</Aside>

<Tabs>

```json
        "riskScore": 4200,
        "usdcSpent": 100,
        "txHash": "0x5a1b2c3d4e5f60718293a4b5c6d7e8f90112233445566778899aabbccddeeff0",
        "blockNumber": 2431902
      }
    ]
  },
  "reputation": "0"

```

Open any `txHash` at `https://robinhoodchain.blockscout.com/tx/<txHash>` to read the `RecommendationCommitted` log for yourself.

## Failure paths

- A malformed `user` value returns 400 `{"error":"user must be a valid address."}`.
- Over 30 requests in 60 seconds from one IP returns 429 `{"error":"Too many requests. Please slow down a moment."}` with a `Retry-After` header.
- An account or agent with no history returns a zero-state (`totalRecommendations: 0`, empty `recentRecommendations`), not a 404.
