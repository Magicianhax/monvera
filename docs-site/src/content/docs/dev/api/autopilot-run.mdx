`POST /api/autopilot/run` triggers one run of your existing Autopilot config right now, inside the same four bounds you already set. It requires a Privy bearer token. The run signs and submits a real on-chain transaction: Vera re-allocates against your saved goal, the delegated signer signs each leg's spend, Vera signs the RiskInference risk assessment, and everything settles as one gas-sponsored transaction.

<Aside type="note" title="Token required">
The request needs `Authorization: Bearer <privy-token>`. A missing or bad token returns `401 {"error":"Please sign in to continue."}`. See [Authentication](/dev/authentication/) for how to obtain the token and the full public-versus-gated matrix.
</Aside>

<Aside type="caution" title="Region-gated and rate-limited">
This route is geo-restricted; a request from a blocked region returns `451 {"error":"Monvera is not available in your region."}` ([availability](/start/where-its-available/)). It is also tight-limited to 6 calls per 60 seconds per account, and only one run per account can be in flight at a time.
</Aside>

Base URL: `https://monvera.best`.

## Trigger one run

`POST /api/autopilot/run` takes no body. It runs the config you set with [POST /api/autopilot](/dev/api/autopilot/), counting the spend against the current period rather than starting a new one.

<Tabs>
<TabItem label="curl">
```bash
curl -X POST https://monvera.best/api/autopilot/run \
  -H "Authorization: Bearer $MONVERA_TOKEN"
```
</TabItem>
<TabItem label="fetch">
```js
const res = await fetch("https://monvera.best/api/autopilot/run", {
  method: "POST",
  headers: { Authorization: `Bearer ${token}` },
});
const result = await res.json();
```
</TabItem>
</Tabs>

A run can take up to two minutes while the transaction is included, so allow for a slow response. Do not retry on timeout; a retry can be refused by the in-flight lock.

## What you get back

The response is the run result. On a settled run `ok` is `true` and `txHash` is the on-chain transaction; on a skipped or failed run `ok` is `false` and `reason` says why.

A settled run:

```json
{
  "ok": true,
  "txHash": "0xabc123…"
}
```

A run that hit a bound or could not settle:

```json
{
  "ok": false,
  "reason": "Period spend cap reached."
}
```

## Response fields

| Field | Type | Description |
| --- | --- | --- |
| `ok` | boolean | `true` if the run settled on-chain, `false` if it was skipped or failed. |
| `txHash` | string \| undefined | The settling transaction hash on chain 4663, present when `ok` is `true`. Open it on [Blockscout](https://robinhoodchain.blockscout.com) to see the trades and the recorded risk assessment. |
| `reason` | string \| undefined | Why the run did not settle, present when `ok` is `false`. |

Bound checks that produce `ok: false` with a `reason`, before anything is signed:

| `reason` | Meaning |
| --- | --- |
| `Not enough cash for this run.` | The funded account's USDG balance is below `amountUsd`. |
| `Period spend cap reached.` | Running would push `spentThisPeriod` past `maxPerPeriodUsd`. |
| `Plan exceeds your risk ceiling.` | Vera's assessed risk for this run is above `riskCeilingBps`. |
| `Autopilot is paused.` | The config is not active. |
| `Amount too small to split across the plan's holdings.` | A leg would fall below the minimum tradable size. |

If the transaction reverts after signing, the response is `{"ok": false, "reason": "Run reverted (tx 0x…)."}`, with the reverting transaction hash you can open on Blockscout.

## Errors you can hit

| Status | Body | When |
| --- | --- | --- |
| 401 | `{"error":"Please sign in to continue."}` | Missing or invalid bearer token. |
| 451 | `{"error":"Monvera is not available in your region."}` | Request from a blocked region. See [Where Monvera is available](/start/where-its-available/). |
| 400 | `{"error":"No autopilot is configured."}` | You have no config; set one with [POST /api/autopilot](/dev/api/autopilot/) first. |
| 429 | `{"error":"Too many requests. Please slow down a moment."}` | More than 6 calls in 60 seconds, or a run is already in flight (that case returns `Retry-After: 30`). |
| 500 | `{"error":"Something went wrong. Please try again."}` | The run threw before returning a result. |

Every settled run is appended to the audit trail at [GET /api/autopilot/runs](/dev/api/autopilot-runs/), whether it succeeded, was skipped, or errored.
