import { Steps, Tabs, TabItem, Aside } from '@astrojs/starlight/components';

Two token-gated POSTs run the accountable-AI flow: `POST /api/allocate` turns a goal and an amount into a named draft plan, and `POST /api/commit-plan` runs one gas-sponsored ERC-4337 userOp that settles the trades on Arcus and records Vera's signed risk assessment in the same transaction. Both need a Privy bearer token. This page uses the canonical "Steady Growth" plan over Apple (AAPL), Nvidia (NVDA), the S&P 500 (SPY), and US Treasuries (SGOV) on chain 4663.

<Aside type="note">
Get a Privy bearer token first. See [authentication](/dev/authentication/) for how to obtain one and where to put it. Every request on this page sends `Authorization: Bearer <privy-token>`.
</Aside>

## Turn a goal into a draft plan

`POST /api/allocate` takes a plain-language goal and a USDG amount and returns a named draft plan: a set of legs, each with an asset, a weight, a one-line reason, and a plain risk read, plus the plan's assessed risk and a ceiling. The bearer token identifies the account the plan is built for.

<Tabs>
<TabItem label="curl">
```bash
curl -X POST "https://monvera.best/api/allocate" \
  -H "Authorization: Bearer $PRIVY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"goal":"grow my money steadily for five years","amountUsdg":"250"}'
```
</TabItem>
<TabItem label="fetch">
```js
const res = await fetch("https://monvera.best/api/allocate", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${privyToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    goal: "grow my money steadily for five years",
    amountUsdg: "250",
  }),
});
const plan = await res.json();
console.log(plan);
```
</TabItem>
</Tabs>

The draft plan comes back named "Steady Growth" with four legs. Each leg carries the asset token address on chain 4663 (AAPL `0xaF3D76f1834A1d425780943C99Ea8A608f8a93f9`, NVDA `0xd0601CE157Db5bdC3162BbaC2a2C8aF5320D9EEC`, SPY `0x117cc2133c37B721F49dE2A7a74833232B3B4C0C`, SGOV `0x92FD66527192E3e61d4DDd13322Aa222DE86F9B5`), its weight, its reason, and its risk read. The plan also carries a `planId`, an `assessedRisk`, and a `maxRisk`. Nothing has been signed or spent yet.

<Aside type="caution">
`allocate` allows 12 requests per 60 seconds per user. A malformed body returns `400 {"error":"Invalid request."}`; a missing or bad token returns `401 {"error":"Please sign in to continue."}`. See [errors](/dev/errors/).
</Aside>

## The RiskInference payload Vera signs

Vera signs a `RiskInference` struct, not the whole plan. This is the exact EIP-712 typed data her signing key (`agentSigner`) signs, and it is what gets verified on-chain when the plan commits:

```
RiskInference(bytes32 planId, uint16 assessedRisk, uint16 maxRisk, uint256 expiry)
```

The domain binds the signature to the deployed VeraRecord contract on chain 4663:

```json
{
  "name": "VeraRecord",
  "version": "1",
  "chainId": 4663,
  "verifyingContract": "0x7ff1a5ee19330c165146488a7ad8af6cb41da1df"
}
```

A signed payload for the "Steady Growth" plan looks like this. `assessedRisk` is Vera's read; `maxRisk` is the ceiling the plan must stay under; `expiry` is a Unix timestamp after which the assessment is stale:

```json
{
  "planId": "0x9f2c...a41b",
  "assessedRisk": 38,
  "maxRisk": 60,
  "expiry": 1751990400
}
```

Vera's signature over this struct proves she authored this exact risk assessment at this time. It does not promise the plan makes money and is not investment advice. See [is this investment advice](/safety/is-this-investment-advice/).

## Commit the plan in one sponsored transaction

`POST /api/commit-plan` submits the plan and runs the single ERC-4337 userOp that settles every leg on Arcus and calls `VeraRecord.record(...)` in the same atomic transaction. The record of Vera's signed risk assessment lands in the same block as the buys, so it cannot be edited after the fact. Monvera sponsors the gas through Pimlico, so the account pays no network fee.

<Tabs>
<TabItem label="curl">
```bash
curl -X POST "https://monvera.best/api/commit-plan" \
  -H "Authorization: Bearer $PRIVY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"planId":"0x9f2c...a41b","address":"0xYourSmartAccountAddress"}'
```
</TabItem>
<TabItem label="fetch">
```js
const res = await fetch("https://monvera.best/api/commit-plan", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${privyToken}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    planId: "0x9f2c...a41b",
    address: "0xYourSmartAccountAddress",
  }),
});
const receipt = await res.json();
console.log(receipt.txHash);
```
</TabItem>
</Tabs>

On success you get a transaction hash. Open it on Blockscout at `https://robinhoodchain.blockscout.com` and you will see a `RecommendationCommitted(planId, user, recHash, riskScore, agentId)` log and an `AllocationExecuted(planId, user, usdcSpent, legCount)` log emitted by `0x7ff1a5ee19330c165146488a7ad8af6cb41da1df`. That is the checkable record.

<Aside type="caution">
The on-chain verify path reverts the whole transaction, so a failed commit spends nothing. It reverts with `InferenceExpired()` if the assessment expired before the block, `RiskCeilingBreached(assessed, maxRisk)` if `assessedRisk` exceeds `maxRisk`, `BadSigner(recovered)` if the recovered signer is not the current `agentSigner()`, and `PlanAlreadyRecorded(planId)` if you commit the same `planId` twice. `commit-plan` allows 20 requests per 60 seconds per user.
</Aside>

## Confirm the record yourself

<Steps>

1. Read `agentSigner()` on `0x7ff1a5ee19330c165146488a7ad8af6cb41da1df` to get the current trusted signer (it can rotate, so read it live).

2. Pull the `RecommendationCommitted` log from your transaction on Blockscout.

3. ECDSA-recover the signer of the `RiskInference` payload and assert it equals `agentSigner()`.

</Steps>

The full runnable recipe, with the public-RPC 10,000-block `eth_getLogs` cap and the fallback through `/api/vera-record`, is on [verify Vera](/dev/verify-vera/).
