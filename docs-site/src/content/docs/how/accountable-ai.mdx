Vera signs a risk assessment for every plan, and one transaction both buys your stocks and writes that signed assessment on-chain, so the record cannot be edited afterward. This page traces that flow end to end and names the exact contract, struct, and event you can check yourself.

Two signatures happen, and they mean different things. Vera signs the **risk assessment** (a small typed struct that proves she authored this exact risk call). You separately sign the **spend** (the user operation that authorizes the money). Do not blur them: Vera's signature proves authorship, not that the plan will make money.

## The flow, from goal to permanent record

<Steps>

1. **You give a goal and an amount.** For example, "grow my money steadily for five years" and $500. Vera turns that into a named plan, "Steady Growth", over four holdings: Apple (AAPL), Nvidia (NVDA), the S&P 500 (SPY), and US Treasuries (SGOV).

2. **Vera signs a risk assessment.** Her signing key (her `agentSigner`) produces an EIP-712 signature over a `RiskInference` struct that binds this plan id to an assessed risk, a risk ceiling, and an expiry. The signature is authorship: it proves the agent, not a person, authored this risk call.

3. **You sign the spend.** You approve one ERC-4337 user operation (the batched transaction). This is where you, not Vera, authorize the money to move.

4. **One transaction trades and records.** Trades execute via Arcus spot RFQ (a request-for-quote venue that returns a firm executable price). The Arcus settle calls and the `VeraRecord.record(...)` call are batched into a single gas-sponsored user operation. The trade and the signed risk assessment land in the same transaction.

5. **The record is permanent.** `VeraRecord` verifies Vera's signature on-chain and emits `RecommendationCommitted` and `AllocationExecuted`. The plan id is single-use, so the same record cannot be written twice or edited later.

</Steps>

<Aside type="note">
On chain 4663 the on-chain entrypoint is `VeraRecord.record(...)`, not `investWithAI`. `StaxExecutor.investWithAI` and `InferenceVerifier` are Mantle-era artifacts and are not used here.
</Aside>

## The contract that verifies and records

The verify-and-record contract (`VeraRecord`) lives at `0x7ff1a5ee19330c165146488a7ad8af6cb41da1df` on chain 4663. The frontend calls one function, batched with the Arcus settle calls in the same sponsored user operation:

```solidity
function record(
  bytes32 planId, bytes32 recHash, uint16 assessedRisk, uint16 maxRisk,
  uint256 expiry, bytes calldata signature, address user, uint256 agentId,
  uint256 usdSpent, uint256 legCount
) external
```

Because `record` runs inside the same transaction as the buys, there is no window where the trades exist without the signed assessment, or the assessment without the trades.

## What Vera signs

Vera signs a `RiskInference` struct under the EIP-712 domain named `VeraRecord`:

```solidity
// RISK_TYPEHASH
keccak256("RiskInference(bytes32 planId,uint16 assessedRisk,uint16 maxRisk,uint256 expiry)")
```

```js
// EIP-712 domain used by the signer and the deployed contract
const domain = {
  name: "VeraRecord",
  version: "1",
  chainId: 4663,
  verifyingContract: "0x7ff1a5ee19330c165146488a7ad8af6cb41da1df",
};
```

The signer to check against is whatever `agentSigner()` returns live. It can rotate, so read it rather than trusting a hardcoded value (last known: `0xe532105523d4eD559c3a53E3E82D616bE1a085c5`):

```bash
cast call 0x7ff1a5ee19330c165146488a7ad8af6cb41da1df "agentSigner()(address)" \
  --rpc-url https://rpc.mainnet.chain.robinhood.com
```

Vera is agent #1 in Monvera's `IdentityRegistry` at `0x751ae640cfa816404b017fbb8234dd21abafbbdc`. Her canonical ERC-8004 identity is registered separately on Base (`8453:58228`). Both are documented on [Verify Vera](/dev/verify-vera/).

## What the transaction reverts on

The record fails, reverting the whole transaction (including the trades), if the signed assessment does not hold up:

- `PlanAlreadyRecorded(planId)` if this plan id was already recorded (single-use replay guard).
- `InferenceExpired()` if `block.timestamp` is past `expiry`.
- `RiskCeilingBreached(assessed, maxRisk)` if `assessedRisk` exceeds `maxRisk`.
- `BadSigner(recovered)` if the recovered signer is not `agentSigner()`.

A stale or out-of-bounds assessment cannot be recorded quietly next to a completed trade. Either both land together or neither does.

## The events that prove it happened

On success, `VeraRecord` emits two events you can pull from Blockscout:

```solidity
event RecommendationCommitted(bytes32 indexed planId, address indexed user, bytes32 recHash, uint16 riskScore, uint256 agentId);
event AllocationExecuted(bytes32 indexed planId, address indexed user, uint256 usdcSpent, uint256 legCount);
```

## Check a record yourself

`GET /api/vera-record` is public (no token) and returns the recorded assessments for an account, so you can confirm a plan without trusting the app UI:

<Tabs>
<TabItem label="curl">

```bash
curl "https://monvera.best/api/vera-record?user=<your-account-address>"
```

</TabItem>
<TabItem label="fetch">

```js
const res = await fetch(
  "https://monvera.best/api/vera-record?user=<your-account-address>"
);
const data = await res.json();
```

</TabItem>
</Tabs>

Public reads of `/api/vera-record` are rate limited to 30 requests per 60 seconds per IP; a caller over the limit gets `429` with `{"error":"Too many requests. Please slow down a moment."}` and a `Retry-After` header. For the full runnable chain (read the agent card, recover the signer, match it to `agentSigner()`), see [Verify Vera](/dev/verify-vera/). Public RPC caps `eth_getLogs` at 10,000 blocks, so full history goes through `/api/vera-record` rather than a raw log scan.

## What the signature proves and what it does not

The signature proves Vera authored this exact risk assessment at this time, and that it is recorded unalterably alongside the trades. It does not promise a return and is not advice. Vera can be wrong; see [how Vera decides and where she can be wrong](/how/how-vera-decides/). For availability, the not-advice line, and what has not been audited, see [where Monvera is available](/start/where-its-available/) and [staying safe](/safety/staying-safe-from-scams/).
